# Data provider

The app no longer includes demo mode; historical references to demo data below describe older versions. Provider failures do not substitute fictional fixtures.

The ESPN scoreboard is an unofficial source. MatchRadar uses the same route for two competitions: `.../soccer/eng.1/scoreboard` (Premier League) and `.../soccer/uefa.champions/scoreboard` (UEFA Champions League). On 28 October 2026, a date-range request to `eng.1` returned HTTP 400; a single-day request (`dates=20261031`) returned HTTP 200 with eight events, and a monthly request (`dates=202610`) returned HTTP 200 with 38 events. On 6 November 2026, `uefa.champions` monthly queries returned 36 events for `202610` and 36 for `202611`, the day query for `20261106` correctly returned an empty schedule, and a date-range request again returned HTTP 400. These observations are not a provider guarantee.

The adapter fetches the calendar months covering the selected competition's fixture window — yesterday through 14 days for the Premier League and yesterday through 30 days for the sparser Champions League — at most every six hours unless the user refreshes. It separately requests today's scoreboard at the adaptive live polling cadence (and yesterday if a cached match from that day is still live). Matches are merged by provider ID, with the daily score taking precedence. ESPN timestamps without seconds are normalized to UTC. An empty events array is a successful empty schedule; errors preserve the existing snapshot and include the query and status in `provider.log` in the app data directory. Malformed individual fixtures are skipped. The source is unofficial, may change, and carries no licensing or availability guarantee. Demo data is never used to fill gaps in the live feed.

## Independent fixture and scoreboard refresh (F03)

Monthly and daily requests produce separate validated outcomes: no valid response, valid data (including an empty array), or valid partial batch data plus an error. A failed second month/day request no longer discards the first successful response. Batch requests stop after HTTP 429 or an explicit Retry-After; a fixture rate-limit response also defers daily requests. Existing adaptive polling, numeric Retry-After and exponential backoff remain; broader F19 deadline/date-header behavior is unchanged.

`fixtureUpdatedAt` advances only when every requested fixture-month query succeeds. `updatedAt` remains the last fully successful daily-score batch time; fixture-only success does not advance it. `fixtureError` and `scoreError` retain each source's last failure until a successful response from that source; skipping a cached source neither confirms it nor clears its error. `partial` and the aggregate error distinguish partial updates from a completely failed refresh. These fields have backward-compatible defaults in persisted snapshots.

Each competition now owns its own status entry under `leagueStatus` (keyed by the stable slug `eng.1` / `uefa.champions`), including fixture/score timestamps and errors plus results-cache timestamps. The legacy aggregate fields remain for old saves and are rebuilt from the per-competition entries; a legacy snapshot's global freshness is migrated once to the Premier League entry. A failure or valid empty response for one competition never removes or rewrites the other's fixtures, results or status. Only an aggregate `partial` update is reported when at least one competition responded successfully in the cycle.

Complete monthly responses reconcile missing upcoming fixtures; partial/failed months retain unseen cached fixtures. Active cached matches are retained as saved observations when absent from new fixtures, within the competition-specific yesterday-through-lookahead UTC window (14 days for the Premier League, 30 for the Champions League). For an unchanged kickoff, a monthly scheduled/unknown placeholder does not erase known progress; new kickoff/team metadata and explicit postponed/cancelled/final statuses take precedence. Valid daily updates then override by stable match ID. Both-source failure preserves cached fixture values and timestamps, marking unconfirmed active scores as saved. ESPN event IDs are globally allocated; each match additionally carries its competition so cross-competition data, results and detail caches cannot be confused.

Only active matches present in successful daily response data are shown as confirmed scores. Other active observations carry `scoreStale`, appear under saved/mixed live headings, and do not advance live notification baselines. Restored active matches also start as saved until a new daily response confirms them; restoring cache never advances source times. Scheduled reminders keep their existing behavior. Partial daily batches can confirm returned matches without falsely advancing the whole scoreboard batch timestamp. F04 delivery retries are independent of provider polling; see `ARCHITECTURE.md`.

| Fixtures | Scores | Result |
| --- | --- | --- |
| Success | Success | Reconcile fixtures, apply scores, advance both source times |
| Success | Failure | Keep new fixtures and appropriate known progress, advance fixture time only, show partial failure/saved scores |
| Failure | Success | Retain cached schedule, merge daily updates, advance scoreboard time only, show fixture failure |
| Failure | Failure | Retain cache and source times, show failure and retain backoff |

Deterministic Rust tests cover these result combinations, empty-cache fixture success, saved live data, rescheduling/cancellation, empty schedules, multi-query partial results, malformed responses, UTC boundaries/deduplication, and numeric Retry-After propagation. The consolidated Windows workflow passed the Rust suite in [run 40846643935](https://github.com/awishtodiexz/MatchRadar/actions/runs/40846643935). Frontend tests cover partial status labels and saved-score presentation; see [validation notes](VALIDATION.md) for the limits of this evidence.

## Champions League verification — 6 November 2026

Direct probes confirmed the `uefa.champions` scoreboard and summary shapes. Monthly scoreboards for October and November 2026 each returned 36 events with the same fields used by the Premier League normalizer (`id`, `date`, `status.type`, competitions/competitors with roles, scores and team logos); the daily query for a date with no fixtures returned a valid empty `events` array. `uefa.champions/summary?event=401915418` (Lens 2–1 Sporting CP) returned HTTP 200 with 22 key events, two boxscore teams and two rosters, matching the existing summary parser.

The same normalizer therefore serves both competitions with the competition passed in as configuration; no duplicate provider implementation exists. The Champions League fixture window is 30 days because its league phase is sparse, and its monthly queries can span three calendar months (verified for a 30-day window crossing a month boundary). Daily score queries, Retry-After handling, malformed-response skipping, empty-schedule semantics and the six-hour fixture cadence are unchanged. UCL fixtures were observed but not exercised through the packaged app; see [validation notes](VALIDATION.md).

## Club identities and crests

On 28 October 2026, the monthly scoreboard returned `team.logo`, while the league teams and individual team endpoints returned `team.logos[].href` with default and, often, dark variants. The normalizer accepts trusted image URLs from either shape and uses the canonical ESPN soccer image path for numeric team IDs if needed. In dark mode the frontend first tries ESPN's dark crest variant so navy artwork stays visible, then the normalized/canonical image, then initials on load failure. Light mode starts with the standard image. Candidates are deduplicated and finite. No extra per-fixture HTTP requests are added to polling.

On 6 November 2026 the real PL and UCL team feeds were compared for clubs present in both: all shared clubs use identical ESPN IDs (for example Arsenal `359`, Aston Villa `362`, Liverpool `364`, Manchester City `382`, Manchester United `360`). Favorites therefore stay a single list of team IDs and work across competitions without a mapping layer.

The previous static catalog contained incorrect IDs: Fulham was `376` (Southampton) instead of `370`, and several other clubs were similarly mismatched. The corrected catalog uses ESPN IDs, merges additional fixture teams by ID, and includes crests even for clubs without a current fixture. Legacy saved favorites are migrated once from the old catalog mapping to preserve the clubs users selected; fresh selections are not remapped. Some supported clubs may be outside the current Premier League season and therefore have no fixtures.

Direct HTTP checks returned 200 and `image/png` for all 23 canonical crest URLs in the corrected catalog, including Fulham `370` and West Ham United `371`. This verifies asset availability at the time of the probe, not perpetual availability or Windows WebView delivery. Keep the image-error fallback. These are externally loaded ESPN/provider-owned assets, not bundled artwork or a grant of redistribution rights. Review licensing before public distribution or replacing the provider. The competition shield is original MatchRadar artwork, not the official Premier League logo.

## Match-summary observations (29 October 2026)

The real-data quality campaign rechecked the completed `401879268` and scheduled `401879250` summaries. `gameInfo.venue.fullName` supplied Emirates Stadium and Villa Park respectively. MatchRadar now normalizes this optional name, rejects control characters and bounds it to 200 characters. Old cached summaries deserialize without it. Neither response supplied officials; the scheduled response had no player entries. No referee or lineup is invented when absent. The completed capture includes 11 starters and nine non-starters per team and provider-written goal, card and substitution text. These are point-in-time observations, not a guaranteed schema.

Completed and live summaries also expose `commentary` (with `play.participants` for scorers), roster `jersey`/`formation`/`formationPlace`/`subbedIn`/`subbedOut`. `formationPlace` is a string in current responses (e.g. `"5"`), not a number, so parse both forms. On 7 November 2026 the live Arsenal–Hull City summary had only 6 keyEvents (including delay markers) but 42 commentary entries; the completed Leeds–Tottenham summary had 40 keyEvents and 118 commentary entries. MatchRadar merges unique commentary, requires a clock for timeline placement, and does not invent periods for untimed boilerplate.

Verified `eng.1/summary?event=401879268` (completed) and `401879250` (upcoming). Reduced response fixtures in `tests/fixtures/summary-*.json` retain events, team statistics and rosters, omitting articles, odds, assets and outbound links. Event text is provider-supplied; no goalscorer is inferred. Events deduplicate by provider event ID and sort by period/clock seconds, retaining stoppage-time display strings. Upcoming boxscore season totals are deliberately excluded. Live/halftime summary responses were not available for verification. Provider-owned text/data retain their licensing limitations; these test captures establish no redistribution permission.

On-demand summaries are independently cached and bounded, never requested by card rendering or notifications. Numeric and RFC2822 HTTP-date Retry-After are now parsed for both scoreboards and summaries. Broader scoreboard manual-refresh cooldown hardening is still outstanding.
