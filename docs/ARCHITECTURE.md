# Architecture

The Tauri process owns a normalized snapshot, preferences, a local JSON cache and a single asynchronous refresh loop. React reads snapshots through commands and refreshes on native events. The window can be hidden while the process continues running. The ESPN adapter validates each fixture independently, and failed requests preserve the previous snapshot. Settings and notification identifiers are persisted together.

The poller targets 60 seconds for live fixtures, five minutes when a fixture is within a day and 30 minutes otherwise. Fixture snapshots use monthly queries refreshed every six hours; daily score updates are merged by stable match ID. Manual refresh forces both. Failure delays grow exponentially; numeric Retry-After is honored up to one hour. Failures leave the previous snapshot intact and write diagnostic details to `provider.log`. The implementation has not yet been tested against actual sleep/resume or rate-limit responses.

Settings saves are separate from data refresh. Appearance, pinning, favorites/filtering, and notification preferences persist and emit a snapshot event without waking the poller or changing feed timestamps. Only a demo/live mode transition clears feed data and wakes refresh; a generation counter prevents older requests from repopulating a different mode. The frontend queues partial preference edits, overlays pending edits on snapshots, and rolls back failed saves without discarding later unrelated edits. Rust remains authoritative after persistence.

The root window participates in the taskbar (`skipTaskbar: false`); the permitted frontend minimize command is separate from hide-to-tray. Rust applies pin changes and compact sizing. Compact mode targets a logical height of 460px and width no greater than 390px, respecting narrower windows; expanded dimensions are stored in the snapshot and restored when compact is disabled. The window-state plugin restores first, then compact sizing is applied explicitly to avoid competing startup restores. Native operation/persistence errors are returned to the UI.

Settings deserialize with dark-theme defaults and opacity clamped to 70–100. `teamCatalogVersion` migrates old favorite IDs once, independently of provider match identities. `expandedSize` stores logical dimensions so display scaling is not baked into the saved expanded size. Native window restoration and actual taskbar behavior still require packaged Windows verification.

`src-tauri/src/alerts.rs` plans notifications independently of native delivery so eligibility, timing, and persistence can be tested deterministically. Settings hold `matchAlerts` keyed by stable match ID: missing uses followed-team switches, enabled opts into reminder/start/goal alerts regardless of those switches, and disabled mutes that match even when a club is followed. Resetting match bells restores team defaults. The reminder lead time is shared. A bell opt-in explicitly enables goal alerts for that match; team goals remain off by default.

Match overrides, observation baselines, score high-water totals, and sent event IDs persist in the local snapshot. Enabling/resetting an override re-primes its observation while retaining the score ceiling; the next successful observation establishes a baseline instead of reporting historical starts or goals. Stale observations and score corrections are suppressed conservatively; a legitimate goal coinciding with the first observation or a rebound to a previously observed total may be skipped. Team and match eligibility feed one event planner, so overlapping subscriptions cannot generate two candidates for the same event. Native delivery errors are logged, and only successful delivery records a sent ID.

Expiry is derived by Rust from the known kickoff, not trusted from the client. Completed/cancelled overrides are removed after a day from kickoff; absent or unresolved fixtures retain overrides until 30 days after the last known kickoff. A changed kickoff extends expiry. Cleanup runs at startup and successful polling, preserving overrides across short outages. Saving a bell preference does not cause network refreshes. Compact remains off for new installations, and saved compact/expanded preferences are preserved.
